# Подключение к Railway + MySQL

Сайт (`index.html`, `admin.html`) и небольшой API-сервер (`server.js`) работают
как **один сервис** на Railway. Сервер сам раздаёт HTML-страницы и обслуживает
запросы к базе данных — отдельный хостинг для фронтенда не нужен.

Почему нужен сервер, а не только база: в отличие от некоторых сервисов,
MySQL не даёт готового API для браузера — обращаться к базе напрямую из
JavaScript на странице нельзя (да и небезопасно). Поэтому между сайтом и
базой стоит `server.js` на Node.js/Express.

## Структура проекта

```
hamabozor-main/
  index.html         — сайт (магазин)
  admin.html         — админ-панель
  server.js          — API-сервер (Express)
  package.json       — зависимости сервера
  schema.sql          — SQL для создания таблицы заказов
  hash-password.js   — генерация пароля администратора
  .env.example        — какие переменные окружения нужны
```

## Шаг 1. Создайте проект на Railway

1. Зайдите на [railway.app](https://railway.app), войдите через GitHub.
2. **New Project → Deploy from GitHub repo** — выберите репозиторий с этим кодом.
   (Если репозиторий ещё не запушен в GitHub — сначала запушьте, Railway разворачивает именно из git.)

## Шаг 2. Добавьте базу MySQL

1. В этом же проекте Railway: **+ New → Database → Add MySQL**.
2. Railway создаст базу и сам добавит переменные подключения (`MYSQL_URL` и др.) —
   их не нужно вписывать руками, если сервис и база в одном проекте Railway.

## Шаг 3. Создайте таблицу заказов

1. Откройте сервис с MySQL → вкладку **Data** (или **Connect**, чтобы подключиться внешним MySQL-клиентом, например TablePlus/DBeaver).
2. Выполните содержимое файла `schema.sql` — появится таблица `orders`.

## Шаг 4. Настройте переменные окружения сервиса с сервером

Откройте сервис с `server.js` на Railway → вкладка **Variables** и добавьте:

| Переменная | Значение |
|---|---|
| `JWT_SECRET` | любая длинная случайная строка (для подписи входа) |
| `ADMIN_EMAIL` | email, под которым будете входить в `admin.html` |
| `ADMIN_PASSWORD_HASH` | хэш пароля — см. шаг 5 |
| `OWNER_TELEGRAM_CHAT_ID` | (необязательно) ваш chat_id в Telegram — сюда раз в день придёт сводка по "мёртвому" товару и клиентам, которым пора напомнить о себе. Использует тот же бот, что и `TELEGRAM_BOT_TOKEN`. Чтобы узнать свой chat_id — напишите боту любое сообщение, затем откройте `https://api.telegram.org/bot<ВАШ_ТОКЕН>/getUpdates` и найдите `chat.id` в ответе |
| `DIGEST_HOUR` | (необязательно) час отправки сводки, 0–23, по умолчанию 9 |
| `TZ` | (рекомендуется) `Asia/Dushanbe` — чтобы `DIGEST_HOUR` считался по местному времени, а не по времени сервера Railway |

`MYSQL_URL` добавлять не нужно — Railway подставит её сам, если база и сервер в одном проекте (можно связать через **Variable Reference** на вкладке Variables, если Railway не сделал это автоматически).

## Шаг 5. Получите хэш пароля администратора

Локально на своём компьютере (там, где склонирован репозиторий):

```bash
npm install
node hash-password.js ВАШ_ПАРОЛЬ
```

Скопируйте то, что выведется (длинная строка вида `$2a$10$...`) в переменную `ADMIN_PASSWORD_HASH` на Railway.

## Шаг 6. Деплой

Railway сам запускает `npm install` и `npm start` при каждом пуше в git — ничего
дополнительно нажимать не нужно. После деплоя Railway даст публичный URL вида
`https://ваш-проект.up.railway.app` — по нему откроется сайт, а `admin.html` —
по адресу `https://ваш-проект.up.railway.app/admin.html`.

## Шаг 7. Проверка

1. Откройте сайт, добавьте товар в корзину, оформите заказ.
2. Откройте `/admin.html`, войдите email/паролем из шага 5 — заказ должен появиться.
3. Смените статус заказа, обновите страницу — статус должен сохраниться.

## Локальный запуск (для проверки перед деплоем)

```bash
npm install
cp .env.example .env      # затем впишите свои значения в .env
npm start
```

Откройте `http://localhost:3000`.

## Домен

Как и договаривались — сейчас всё работает на адресе от Railway, свой домен
подключите позже в настройках сервиса на Railway (**Settings → Networking → Custom Domain**), когда всё будет проверено.

## На будущее

Telegram-бот в `index.html` сейчас вызывается прямо из браузера, и токен
бота виден любому в исходном коде страницы. Раз уж появился свой сервер —
имеет смысл перенести отправку в Telegram на сервер (эндпоинт вроде
`POST /api/orders` уже мог бы сам слать сообщение в Telegram), чтобы токен
не был публичным. Могу сделать этот шаг отдельно, если нужно.
