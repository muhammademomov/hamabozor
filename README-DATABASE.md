# Подключение базы данных (Supabase)

Сайт использует **Supabase** — бесплатный сервис базы данных (Postgres) с готовым API.
Отдельный backend-сервер писать не нужно: `index.html` и `admin.html` обращаются
к базе напрямую из браузера, безопасность обеспечивают правила доступа (RLS),
уже прописанные в `supabase-schema.sql`.

## Шаг 1. Создайте проект

1. Зайдите на [supabase.com](https://supabase.com) и зарегистрируйтесь.
2. Нажмите **New project**, придумайте пароль для базы данных (сохраните его отдельно) и дождитесь создания проекта (1–2 минуты).

## Шаг 2. Создайте таблицу заказов

1. В левом меню откройте **SQL Editor** → **New query**.
2. Откройте файл `supabase-schema.sql` из этого проекта, скопируйте всё содержимое и вставьте в редактор.
3. Нажмите **Run**. Появится таблица `orders` с уже настроенной защитой доступа.

## Шаг 3. Возьмите ключи подключения

1. В левом меню: **Project Settings → API**.
2. Скопируйте:
   - **Project URL** (например `https://abcdefgh.supabase.co`)
   - **anon public** ключ (длинная строка)

## Шаг 4. Впишите ключи в файлы сайта

В **обоих** файлах — `index.html` и `admin.html` — найдите блок:

```js
const SUPABASE_URL = "https://YOUR-PROJECT.supabase.co";
const SUPABASE_ANON_KEY = "YOUR_ANON_PUBLIC_KEY";
```

и замените на свои значения из шага 3. Значения должны быть **одинаковыми** в обоих файлах.

> Ключ `anon public` не секретный — его специально можно показывать в коде браузера,
> реальная защита данных обеспечивается правилами доступа (RLS) в базе, а не тем,
> что ключ скрыт.

## Шаг 5. Создайте вход для администратора

Раньше в админку заходили по паролю в коде — теперь это настоящий логин через Supabase.

1. В левом меню: **Authentication → Users → Add user**.
2. Укажите email и пароль, под которыми вы будете заходить в `admin.html`.
3. **Отключите публичную регистрацию**, чтобы никто посторонний не мог сам себе завести аккаунт:
   **Authentication → Providers → Email** → выключите "Allow new users to sign up".

## Шаг 6. Проверка

1. Откройте `index.html`, добавьте товар в корзину и оформите заказ.
2. Откройте `admin.html`, войдите email/паролем из шага 5 — заказ должен появиться в таблице.
3. Смените статус заказа в админке, обновите страницу — статус должен сохраниться.

## Дальше — публикация через git

Файлы статические (HTML/CSS/JS), поэтому подойдёт любой git-хостинг:
GitHub Pages, Netlify или Vercel — просто закиньте репозиторий, отдельная
сборка (build) не нужна. Домен подключается в настройках хостинга уже
после того, как всё проверено и работает.

## Что уже сделано в коде

- **index.html**: при оформлении заказа (кнопка WhatsApp или Telegram) заказ
  сначала сохраняется в таблицу `orders`, а затем, как и раньше, открывается
  WhatsApp/Telegram с текстом заказа.
- **admin.html**: вместо тестового списка заказов (`MOCK_ORDERS`) при входе
  подгружаются реальные заказы из базы (`loadOrders()`), список обновляется
  автоматически каждые 20 секунд и по кнопке «↻ Обновить». Смена статуса
  заказа сразу сохраняется в базу.

## На будущее

- Telegram-бот сейчас вызывается прямо из браузера, и токен бота виден
  любому в исходном коде страницы. Для реального магазина это стоит
  вынести на отдельный сервер (например, Supabase Edge Function), чтобы
  токен не был публичным — можем сделать отдельным шагом.
